# Living Survey: claude

## Introduction

This document collects the scientific literature regarding **claude**.

## Capabilities and Benchmarks

Recent evaluations highlight both the strengths and systematic biases of Claude models across various domains. Multimodal Large Language Models (MLLMs), including Claude, have been shown to systematically overrate facial attractiveness compared to human judgments, though they maintain strong rank-order correlations [^2609.02512]. In scientific claim validation, frontier models like Claude Opus 4.8 and Claude Fable 5 demonstrate high competitiveness, with pairing strategies proving more impactful than model swaps alone [^2609.00654]. Vision-language models such as claude-fable-5 have also surpassed young adults in detecting AI-generated portraits, although their calibration remains less balanced than human criteria [^2608.30210]. Furthermore, studies on behavioral rigidity indicate that Claude models are consistently the most rigid among frontier LLMs, resisting correction more than GPT or distilled variants, which reflects deeper training methodologies [^10.5281_zenodo.19040362]. Societal bias evaluations in guardrailed LVLMs reveal that while proprietary models like Claude exhibit lower bias than open-source alternatives, they still undesirably utilize demographic cues in person-irrelevant tasks [^2608.29590].

## Agentic Software Engineering and Tool Use

Claude Code and related agent harnesses have become central to agentic software engineering, prompting extensive research into their tool-use capabilities, security, and efficiency. Frameworks like HEART leverage agent-native reusable tool primitives to orchestrate Claude-4.6-Sonnet, significantly outperforming SFT-based models and reducing API costs by up to 85% [^2609.01736]. In educational settings, Spec-Driven Development utilizing Claude Code increases implementation throughput but requires instructor verification to prevent superficial code comprehension [^2608.30572]. Security analyses reveal novel attack vectors in context assembly, such as MessageRole and Cross-Scope Context Privilege Escalation, which can lead to full agent compromise in harnesses like Claude Code [^2609.01222]. To mitigate these risks, Defense-as-Skill implements runtime guards (e.g., SkillSonar) alongside untrusted task skills, substantially reducing attack success rates on Claude Code while maintaining utility [^2609.01487]. Additionally, graph-grounded software knowledge retrieval improves first-attempt execution reliability for Claude Code in complex ecosystems like ROOT [^2609.01095]. Memory management in production agents using Claude Code faces conditioning problems during context compression; exact gradient-equivalent corrections like LogitTree and SDCC help close the train-deployment gap [^2609.00865]. Cross-episode agent memory can be optimized using invalidation contracts that attach version stamps to recovery suggestions, though compliance varies significantly between Claude Haiku 4.5 and Claude Sonnet 5 due to input-schema conservatism [^2609.00243].

## Safety, Alignment, and Red-Teaming

The safety and alignment of Claude models remain active areas of investigation, particularly regarding dangerous capabilities, prompt injection, and multi-turn vulnerabilities. The FUSE framework evaluates dangerous capabilities across three orthogonal pipelines (Knowledge, Defense, Harm), revealing that newer Claude models deepen knowledge while only partially improving defense, indicating that scaling does not uniformly translate to safety [^2609.02168]. Temporal analysis of public-sharing labels in MCP-to-A2A configurations shows that adding explicit PUBLIC headers is descriptively associated with higher verbatim data egress in Claude Sonnet 5, highlighting model-dependent safety behaviors [^2609.01693]. Red-teaming efforts using evolutionary quality-diversity search (EvoFlint) expose that Claude Sonnet 4.6 remains vulnerable to multi-turn attacks, with attack success rates reaching 35.8% [^2609.00487]. Similarly, the ECLIPSE framework demonstrates self-evolving stealthy prompt injection against long-horizon agentic systems, achieving high success rates against Claude Code even under common safety filters [^2608.30441]. For compute use agents, the SIR framework composes stealthy indirect prompt injections from reusable principles, raising attack success rates on Claude Opus 4.8 from 4% to 24% while maintaining benign task completion [^2608.30207]. Creative prompting evaluations (IDEAFix) show that Claude models participate in divergent thinking benchmarks, though their outputs are subject to fixation effects that structured prompting can mitigate [^10.5281_zenodo.19838006].

## Training, Memory, and Context Management

Advancements in training and context handling for Claude-based agents focus on consistency, feedback mechanisms, and ontological properties. Training agents on compressed contexts often causes train-inference mismatch; self-distillation for conditioning consistency (SDCC) minimizes forward KL divergence between compressed and reconstructed prefixes, improving rollout rewards [^2609.00865]. Feedback-driven code repair studies indicate that while test feedback is strongest for Python, its effectiveness ranking differs in Java, suggesting that Claude 3.5 Sonnet's repair capabilities are sensitive to benchmark construction and tooling ecosystems [^2609.00362]. Step-level render-grounded refinement (ReDeck) decomposes slide revision into atomic edits, providing renderer-derived observations that significantly improve spatial and semantic quality for Claude-4.6 [^2609.00194]. Data science code generation benchmarks (DSEffi-Bench) reveal that efficiency deficits in models like Claude-Opus-4.6 often stem from domain-specific root causes rather than algorithmic complexity, guiding taxonomy-guided optimization [^2608.30248]. Theoretical frameworks treating LLM non-determinism as an ontological property model Claude's output space as a semantic manifold, introducing metrics like Silent Authority Transfer to quantify decision boundary drift during substrate updates [^10.5281_zenodo.19536191].
